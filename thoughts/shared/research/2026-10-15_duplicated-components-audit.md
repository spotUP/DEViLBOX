# Duplicated components audit

Read-only audit, 2026-10-15. Ledger: `thoughts/spot/todos.md:679`.

## Method and its limits

- User counts come from one import index (`grep -rnE "from '...'|import('...')"` over `src/**/*.ts(x)`, `__tests__` excluded) matched on the path suffix `/<Name>'`, plus a JSX check (`<Name `) for pieces re-exported through a barrel (`instruments/shared/index.ts`). A barrel-only consumer or a `lazy(() => import())` with a variable path would be missed (not verified).
- Counts of "hand-rolled" things are grep counts of a SPELLING (`fixed inset-0`, `<button`, `type="range"`, `ARP_COLUMN`, `ResizeObserver`). They bound the problem; they do not prove completeness. Each row says which spelling was counted.
- FurnaceOrderEditor, GTOrderMatrix and KlysPositionEditor are being moved onto SongOrderMatrix by another agent right now (working tree shows them modified): listed as "in progress", not analysed.
- Nothing was run, rendered or listened to. "Missed fixes" below are derived from reading source and commit messages, not from reproducing the behaviour. Marked UNVERIFIED where I did not read the code path.

## Ranked migration order (most user-visible divergence first)

1. Row 1b: SF2OrderMatrix and CCOrderMatrix onto SongOrderMatrix. Same defect as the example, no one is working on it, and these are read-only click lists next to an editable canvas.
2. Row 3: hand-rolled dialogs, starting with the ones under the 99990 layer (`z-50`, `z-[60]`, `z-[100]`, `z-[9999]`): a Modal opened from them or over them stacks wrong, and phone fit is Modal-only.
3. Row 5: subsong selectors onto `subsongStatus` (one component, slots for SID chip/info and Furnace names). Check first whether native/file sources lack a selector in the editor bar.
4. Row 2: MaxTraxGrid onto format-mode PatternEditorCanvas (largest behavioural gap, largest cost; needs a feasibility probe on sub-columns first).
5. Row 6: view shells drop their ResizeObserver/size/collapsed state once row 1 lands (Hively, Klys, TFMX, SunTronic, Furnace, GT).
6. Row 4: Modal calls `useDialogKeyboard`.
7. Row 7: three scopes onto `useVisualizationAnimation`.
8. Row 8: one ArpTableEditor for 8 instrument controls.
9. Row 9: audit the 8 popover candidates, then move.
10. Rows 11, 14, 10: only with a feasibility probe; row 10 per touched file, never as a sweep.
11. Rows 12, 13: dead code, delete only with per-file owner approval.

Each migration needs one test through the real entry point (the view or dialog mounted) proving the shared piece ran, per the reachability rule, not one test per behaviour.
