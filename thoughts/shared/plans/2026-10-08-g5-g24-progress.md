## Open sub-items, with reasons

- G5 activisionPro: track pointers are s16 relative to tracksOffset (2698): reach ends at 35465, the file is 50942 and the bytes behind the tracks (subsong list, position lists, sample data from 3502) are not free. A grown track has nowhere to go without relocating code-referenced sections.
- G5 benDaglish: same shape (u16 table, tracks end at the table, 4334; the end of the file is 59936 past tracksOffset). Measured: a track appended at the end of the file (u16 offset 0xEA20) makes the original player stop voice 0 (14 Paula writes against 508), so the table is read signed. Written and reverted; the C-port walk accepts it, the 68k player does not.
- G5 daveLowe: per-section command streams under a variable layout; Export has no path for it (the generic layout patch needs a fixed layout). Growing a section needs the section pointers.
- G5 futurePlayer: rows are `speed` interrupts and note starts re-arm every tick (P16 notes); a note command has no home on a blank tick without re-timing the stream. Not designed.
- G5 hippelCoso: rows past a pattern's `-1` terminator are padding; a note there lengthens the pattern, which changes that voice's timing against the other three. The u16 pattern table would allow an append at the end of the file (24340 bytes). Not built: the timing semantics need an owner decision.
- G5 sidmon2: rows are commands with a trailing speed byte; split = shorten the covering command's speed + insert a row; needs the u16 pattern pointer table, `patternDataLen` (u32 at 50) and word alignment moved. Designed like sidmon1, not built.
- G24 futurePlayer, jamcracker: the worklet renders ahead into a ring and resamples; a swap must drop the ring and catch up to the frames PLAYED, not rendered. Not built.
- G24 EaglePlayer family (daveLowe, soundPlayer): `EaglePlayerEngine.writeModule` exists (writeCellToChipRam); not measured (m68k worklet harness not built).
- G24 Hippel (CoSo, 7V, TFMX 4V): the store's `rebuildHippelModule` + `TFMXEngine.reloadModule` path exists and now takes the instrument's key sequence; it goes through the same reload + seek as TFMX (about 30 ms) but is not measured with Hippel songs.
- G24 activisionPro, fred, actionamics, sonicArranger, tfm (TFM Music Maker): own module swaps / track-index routes exist; not measured with their worklets.

## Found

- SoundControl and TFMX note encoders were 24 semitones off their parsers (a typed note came out two octaves away after export); fixed with corpus round-trip tests.
- SoundControl and TFMX exporters rebuilt the module from the grid: SoundControl's output was refused by the player (`sc_create` fails), TFMX dropped every pattern past 128 (188 generated). Both now write the loaded module with the edited words in place; unedited TFMX export is the file byte for byte.
- A survey of `decodeCell(encodeCell(cell)).note` over the corpus shows more mismatches, not investigated: fc (21 of 46 cells), inStereo2 (102 of 144), inStereoAmbiguous (44 of 86), okt (all), mtm, plm, dtm (the last four play through the TypeScript scheduler or libopenmpt, where the layout encoder may be unused).
- `Hively.js` does not export `HEAPU8` on the Module; the engine class's `transformJS` adds it. Any harness must pass the engine's own transform.
- `eventsOfVoice` in gridOracle previously dropped the register from its output; fixed (sidmon1AddNoteSounds then needed its pointer registers filtered properly).
