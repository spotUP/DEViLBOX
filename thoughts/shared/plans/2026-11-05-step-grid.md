# Step grid: 1 row = 1 song step

## Problem and fixed decision

Owner report: garfield2+.dw plays fast and its notes sit far apart. goldrunner.psf (Sound Factory) shows
the same symptom. Cause: the David Whittaker grid draws one row per 50 Hz tick at speed 1
(`davidWhittakerGrid.ts` header, `DavidWhittakerParser.ts:742-746` sets `initialSpeed = 1`). Sound
Factory draws one row per tick with `initialSpeed 6` (`SoundFactoryParser.ts:712-713`, `:853`).

Owner decision (fixed, do not re-ask): **1 row = 1 song step (`speed` ticks).** Tracker speed comes
from the song. Where the song changes speed, the grid carries an `Fxx` speed effect. This applies to the
whole command-stream class (DW, Hippel, Ben Daglish, Rob Hubbard) plus Sound Factory. DW is first and is
the reference implementation.

Key finding for DW: the walk's `tick` counts 50 Hz frames, including skipped frames, because `walk_tick++`
runs before the frame-skip early return (`davidwhittaker.c:2167-2182`). Rows must be counted in
**processed** ticks. Then apb.dw is also clean. The walk must expose a processed-tick counter
(new field on each event, e.g. `ptick`). The C change is small: increment a second counter after the skip
checks. This is a C/WASM change and a rebuild, not a TS workaround.

## 2. Rule for events between steps

**Chosen: keep row = step and store the remainder as a sub-row tick offset in an effect slot**
(note delay, `EDx`-style; value = `tick - row*speed`, 1..speed-1).

Justification:
- Row = step stays exact, so the playhead advances uniformly at song speed. The scheduler clock
  (`rowSeconds = initialSpeed*2.5/BPM`, `gridClockOracle.ts:18`) stays valid.
- The blockRows carrier is untouched: the carrier stores bytes, not grid positions.
- Edits round-trip: the edit layer turns `row*speed + offset` back into the exact tick.
- Rejected: row split (insert extra rows at sub-step events). It breaks uniform row length, needs per-row
  speed changes (`Fxx` on every split), and makes pattern length data-dependent.
- Rejected: fold into the row (current Rob Hubbard behaviour). It loses timing; RH moves to the offset
  rule too.

For DW and Hippel the offset is almost always 0 (garfield: 0 of 2581). For BD and SF, the offset carries
the few off-grid durations (motorhead 3/4-tick notes, goldrunner 1665).

Step rule for duration-only formats (BD, SF): the step is the largest `d` that divides the most common
onset delta and also divides at least 90% of all onset deltas (measured: motorhead 5, mickey_mouse 8,
goldrunner 6). Fallback is 1 (today's behaviour). The 90% threshold is an OPEN owner decision. The rule
is one pure function `deriveStepFromDurations(deltas)`.

## 5. Risks and open owner decisions

- R1 (OPEN) Frame-skip songs (apb.dw `extra_counter`, BD `counter=6`, DW delay counter
  `davidwhittaker.c:1567-1571`): steps are counted in processed ticks, but processed ticks run at
  50x5/6 Hz (BPM ~104.17) or `50x(1-dcs/256)` Hz. The scheduler needs fractional BPM, or a per-song
  tick rate. Fractional BPM in the song model and exports is untested. Owner decides: fractional
  `initialBPM`, or a separate tick-rate field.
- R2 (OPEN) BD/SF step threshold (90%). Lower gives coarser grids with more offsets; higher falls back
  to 1 more often.
- R3 `Fxx` needs an effect slot. DW uses 5 slots (`fitEffectColumns`); a row with 5 effects plus a speed
  change or an offset overflows. Proposal: offset and `Fxx` take priority slots; overflow falls back to
  an extra effect column. OPEN if the owner wants a fixed column count.
- R4 Speed change mid-note: `davidWhittakerEdits.ts:98-103` refuses edits there today; S0 handles it by
  resetting the row origin, but the note-length display across a change needs a test.
- R5 Existing saved projects that stored DW/BD/SF grids with tick rows: on load, grids are rebuilt from
  the carrier, so no migration is expected — UNVERIFIED (check persistence of `patterns` for these
  formats).
- R6 Hippel prehistoric_tale first pattern of length 1 — check it is real, not a parse fault.
- R7 Sound Factory second tune not measured; `ben_daglish.c` no-touch status unknown.

## 7. Proposed wording for docs/FORMAT_COMMAND_STREAM_GRID.md (not applied)

§4 (display grid timeline), replace the "row === 50 Hz tick" statement with:

> The display grid has one row per song step. A step is the format's own speed unit: the song speed
> (DW `playing_info.speed`, Hippel song speed, Rob Hubbard `speed`), or, for formats with only per-note
> durations (Ben Daglish, Sound Factory), the step derived from the durations by
> `deriveStepFromDurations`. Count steps in processed replayer ticks, never in 50 Hz frames: frame-skip
> counters make the two differ. The song's `initialSpeed` is the step, and every speed change in the
> stream appears as `Fxx` on the row where it takes effect. An event that falls between steps stays on
> the step row and carries its remainder as a note-delay offset. Never split rows and never fold the
> remainder away. All tick/row conversion goes through `stepRowClock.ts`: the grid builder, the edit
> layer, the live engine and the exporter use the same clock.

§8 step 6, replace with:

> 6. Build the display grid from the walk with `makeRowClock(speedChanges)`: rows = processed ticks per
> step, `initialSpeed` = the song step, `Fxx` at speed changes, offsets for sub-step events. Prove it
> with one reachability test through `parseModuleToSong` that asserts row spacing equals the song step
> and grid speed equals song speed on a real tune.

## Owner decisions (2026-11-05)

- R1: fractional BPM. `initialBPM` carries the effective rate (apb.dw about 104.17). BPM stays the only timing source. Exporters to formats with whole-number BPM round at the export boundary only.
- R2: no threshold and no guessing. The owner answer was "i want the correct solution here no guessing". Rule: count onsets in processed ticks (frame-skip ticks excluded, the same counter as DW D1), then step = GCD of all onset deltas in processed ticks over the whole song. This is exact: every event lands on a row, with no offsets. First, check the format source for a native duration unit; if one exists, use it. If the processed-tick GCD is still 1 on motorhead or mickey_mouse, stop and report the measured deltas. Do not choose a step. `deriveStepFromDurations` with a 90% cut is rejected.
- R3: add a column. Fxx and the offset take priority slots. On overflow, one extra effect column for that song only.
- Scope: all of them, after the pilot. Order: DW pilot (S0, D1-D6), then BD, SF, RH, Hippel, then every row in the section 6 survey through `stepRowClock.ts`.
