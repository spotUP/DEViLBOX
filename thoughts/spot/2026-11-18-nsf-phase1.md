# NSF import, phase 1: per-frame chip state

## What was built

- `third-party/game-music-emu/gme/Nsf_Emu.{h,cpp}`: `play_hook` / `play_hook_data`
  members, called in `run_clocks` right after `GME_FRAME_HOOK` each time a PLAY
  call is set up. Null by default, so normal playback is unchanged (the playback
  emu never sets it).
- `friend struct Nsf_Trace;` added to the private sections of `Nsf_Emu`,
  `Nes_Apu`, `Nes_Vrc6_Apu`, `Nes_Namco_Apu`, `Nes_Fme7_Apu`, `Nes_Vrc7_Apu`,
  `Nes_Fds_Apu` (read access only, no behaviour change).
- `game-music-emu-wasm/src/gme_wasm.cpp`: `Nsf_Trace` plus exports
  `gme_wasm_trace_words/open/run/frame/read/play_hz/close`. The trace runs on a
  second emulator (separate from the playback `emu`), with silence look-ahead
  off, so record 0 is the state right after INIT and record k the state after
  PLAY call k. Before each snapshot the 2A03, MMC5 and FDS are caught up to the
  current CPU time (they run lazily), so envelope and length counters are live.
  The trace renders audio through the real outputs, because GME skips the FDS
  envelope clock when its output is null.
- Record: 390 uint16 words per PLAY call. Offsets are the `T_*` enum in gme_wasm.cpp.
- `gme_wasm_trace_read(addr)` reads $8000-$FFFF through the current bank mapping
  (`Nsf_Emu::pcm_read`), for DPCM sample extraction.
- `src/engine/__tests__/gmeNsfStateTrace.test.ts` traces 1800 frames (30 s) of track 2 of
  dr mario.nsf.

## Per-chip state (what GME models, what the record holds)

| Chip | GME holds | Record holds | Gaps |
|------|-----------|--------------|------|
| 2A03 squares | regs[4], length counter, envelope, sweep result period | regs, length, output volume, $4015 bit, period | none for import |
| 2A03 triangle | regs[4], length, linear counter | regs, length, linear counter, enabled, period | none |
| 2A03 noise | regs[4], length, envelope | regs, length, volume, enabled (mode/period in regs[2]) | none |
| 2A03 DMC | regs[4], bytes left, read address, DAC | regs, bytes left, address, DAC, playing | sample bytes come from `trace_read` |
| VRC6 | 3 x regs[3] | 3 x (regs, period) | none |
| VRC7 | custom patch inst[8], 6 x regs[3] ($10/$20/$30) | same | built-in patch ROM index is in regs[2] high nibble; no envelope phase readout (not needed for notes) |
| FDS | $4040-$4092 as written, mod table 64, env gain, sweep gain, mod position | same | none |
| MMC5 | 2 squares as `Nes_Apu` squares, PCM via $5011 DAC write | 2 squares, PCM DAC | PCM read mode ($5010 bit 0) is not modelled by GME |
| N163 | internal RAM 128 (wave RAM + channel regs $40-$7F) | same | active channel count is in reg $7F bits 4-6 |
| S5B (FME-7) | regs $00-$0D (tone, noise, mixer, volume, envelope) | same | none |

Verified: 2A03 only (dr mario.nsf, chip flags 0): square 1/2 pitch and volume
change, triangle plays with changing pitch, noise volume moves, PLAY rate 60 Hz.

## Converter location (phase 2): furnace-fileops-wasm

Decision: the NSF-to-.fur converter (port of FamiStudio `NsfFile.cs`, MIT) lives in
`furnace-fileops-wasm`, not in `game-music-emu-wasm`.

Reason: the output is a Furnace song. furnace-fileops-wasm already compiles
Furnace's song/instrument/sample/wavetable/pattern model and the .fur writer
(`_fur_save`, `_fur_set_cell`, `_fur_set_wave`, `_fur_set_sample`). Building the
converter in gme-wasm would need a second .fur writer, a duplicate of Furnace's.
The state source is GME. Two ways to feed it, phase 2 picks:
(a) compile the GME NSF sources (Nsf_Emu, Nes_Cpu, the chip APUs) into
furnace-fileops-wasm, so one wasm call goes from NSF bytes to .fur bytes (no TS
between them, matches the "importers are C++ in wasm" rule best); or
(b) TS passes the trace blob from Gme.wasm to FurnaceFileOps.wasm (TS only moves
bytes). Recommendation: (a). GME is LGPL 2.1+, Furnace GPL 2+, compatible.
Cost of (a): about 250 KB more in FurnaceFileOps.wasm (now 901 KB).
Never use NSFImport / NotSoFatso code (GPL, owner rule).

## Open items

- No real VRC6, VRC7, FDS, MMC5, N163 or S5B NSF exists in the repo or on this
  machine (searched public/data/songs, ~/Downloads, other app fixtures; all are
  2A03). Owner to approve adding real files, e.g. from modland: Akumajou Densetsu
  (VRC6), Lagrange Point (VRC7), Gimmick! (S5B), a Namco N163 title, an FDS
  title, Just Breed (MMC5). Then extend gmeNsfStateTrace.test.ts per chip.
- The expansion sections of the record are built from GME fields read in source,
  but no song has exercised them.
- MMC5 PCM read mode is not modelled by GME (rare in NSFs).
- Bank-switched songs: `trace_read` reads the mapping at the time of the last
  record; the converter must read DPCM bytes at the frame the sample starts
  (phase 2 should read samples inside the hook or record $5FF8-$5FFF banks).
